# TPF Assistant

FastAPI API and a separately maintained Angular frontend. The API relies on
Azure App Service Authentication (Easy Auth) for sign-in and checks the Entra
app role `americanusers` before returning user information or processing chat
requests.

## Local development

1. Start the Angular development server:

   ```sh
   cd frontend
   npm install
   npm start
   ```

   The Angular dev server listens on `http://localhost:4200` and proxies `/auth`
   and `/chat` requests to `http://localhost:8000`.

2. In a second terminal, start FastAPI:

   ```sh
   cd backend
   uv run uvicorn main:app --reload --host 0.0.0.0 --port 8000
   ```

   Local API calls return `401` until they pass through an App Service instance
   with Easy Auth enabled. The local sign-in button also requires an Azure-hosted
   Easy Auth instance. Do not add a local or production bypass that trusts
   caller-supplied identity headers.

3. To build the standalone frontend bundle:

   ```sh
   cd frontend
   npm run build
   ```

   FastAPI serves the built files from `frontend/dist/frontend/browser` when
   that directory exists.

## Manual Azure App Service ZIP deployment

Create a deployment ZIP from the repository root with the application files at
the archive root (not inside an extra enclosing directory). Include:

- `main.py`, `auth.py`, `config.py`, `models.py`, and `agent_client.py`
- `requirements.txt` exported from the locked backend dependencies
- `frontend/dist/frontend/browser/` from `npm run build`

Configure the App Service for **Linux, Python 3.13** and enable build automation
(`SCM_DO_BUILD_DURING_DEPLOYMENT=true`) so App Service installs dependencies
from the root `requirements.txt`. Configure this startup command under
**Settings > Configuration > General settings > Startup Command**:

```sh
python -m uvicorn main:app --host 0.0.0.0 --port 8000
```

Deploy the ZIP using the App Service ZIP Deploy endpoint/Kudu credentials and
monitor the deployment in Deployment Center. The app uses `americanusers` as
the required role by default; set `EASYAUTH_REQUIRED_APP_ROLE` if your role
value differs. Configure Easy Auth and the application settings separately in
the Azure portal; secrets and environment-specific settings are not included
in the ZIP.

## Azure authentication and authorization

1. Enable App Service Authentication and configure Microsoft Entra ID as the
   identity provider. Configure the Entra app registration to issue app roles
   in the sign-in token and assign users or groups the `americanusers` role.
2. Ensure Easy Auth is enabled on the same App Service that hosts this FastAPI
   backend. The backend consumes the `X-MS-CLIENT-PRINCIPAL` header generated by
   Easy Auth; it does not accept bearer tokens created by the old demo login.
3. Keep Easy Auth in front of the backend so requests cannot bypass the
   authentication module. If the Angular sign-in screen must render before the
   user signs in, allow anonymous page loads at the platform layer and rely on
   the API dependencies for access control; `/auth/me`, `/chat`, and
   `/chat/stream` reject requests without the Easy Auth principal. Static
   content and `/health` do not contain user data.
4. Set `EASYAUTH_REQUIRED_APP_ROLE` to the exact role value to require. It
   defaults to `americanusers`; role values are case-sensitive. An authenticated
   request without that role receives `403`, and a request with no valid Easy
   Auth principal receives `401`.
5. Use the same origin for the frontend and API in production so the Easy Auth
   session cookie is sent with API calls. The Angular app uses the platform
   `/.auth/login/aad` and `/.auth/logout` endpoints and includes credentials on
   API requests.

Relevant routes:

| Route | Authorization |
| --- | --- |
| `GET /health` | Public readiness information |
| `GET /auth/me` | Authenticated user with the configured app role |
| `POST /chat` | Authenticated user with the configured app role |
| `POST /chat/stream` | Authenticated user with the configured app role |

`CORS_ALLOWED_ORIGINS` remains available for a separately hosted frontend. When
using a different origin, configure the exact frontend origin and verify the
Easy Auth cookie and browser credential policy for that deployment.
